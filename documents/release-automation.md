# Автоматичні релізи

Кожен push у `main` запускає workflow **Build and release**. Після успішної
перевірки він створює GitHub Release з такими файлами:

- `SerialVision.exe` — portable Windows-застосунок;
- `SerialVision-Setup-v*.exe` — Windows-інсталятор Inno Setup;
- `SerialVision-v*.msi` — Windows MSI-інсталятор;
- `serial-vision_*.deb` — пакет Debian/Ubuntu для x86_64;
- `serial-vision-*-source.tar.gz` — вихідний код для Linux.

## Версії

Файл `VERSION` задає стабільну основу `MAJOR.MINOR.PATCH`. Під час CI останнє
число замінюється номером запуску workflow, тому кожен опублікований реліз має
унікальну версію `MAJOR.MINOR.<run number>`. Вихідний архів та всі пакети
одержують ту саму версію. Файл у репозиторії не змінюється автоматично.

## Changelog і відновлення

Опис GitHub Release складається з комітів від попереднього тега та вмісту
`CHANGELOG.md`. Якщо одна зі збірок або тестів не пройшла, реліз не створюється:
виправте причину й зробіть новий push у `main`. Повторний запуск того самого
workflow використовує ту саму версію і може бути виконаний лише після видалення
невдалого або частково створеного релізу з відповідним тегом.
