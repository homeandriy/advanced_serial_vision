# Техборг Serial Vision

Актуалізовано 2026-10-26. Нижче — відкриті технічні задачі та критерії їх
закриття. Нові продуктові можливості ведуться окремо від техборгу.

## Відкриті пункти

### TD-01 · Середній · Атомарне збереження налаштувань

- `MainWindow.save_all_settings()` і методи `SerialVisionService` зберігають
  параметри окремими записами; збій може залишити частково застосовані зміни.
- Зібрати запис налаштувань в одну транзакцію прикладного сервісу. Перезапуск
  локального API узгодити з успішним збереженням і відновленням попереднього стану.
- Критерій: тест штучної помилки підтверджує повне збереження або повний відкат
  параметрів, а інтерфейс коректно показує незбережений стан.

### TD-02 · Середній · Розширення перевірки типів

- Mypy зараз перевіряє лише п'ять модулів ядра з `[tool.mypy]`.
- Поступово додати БД, прикладний сервіс, локальний API, фонові робітники та UI;
  уточнити типи DTO, результатів SQLite і JSON замість розповсюдження `object`/`Any`.
- Критерій: нові модулі включені в обов'язковий `make typecheck` і CI; для них
  виправлені помилки без загального вимкнення перевірок.

### TD-03 · Середній · Поділ головного вікна

- `ui/main_window.py` поєднує побудову екранів, обробники форм, оновлення,
  камеру та керування API. Винесення робітників у `ui/workers.py` — перший крок.
- Послідовно виділити екрани розпізнавання, обладнання, моделей, статистики,
  налаштувань та API, залишивши `MainWindow` координацію навігації й життєвого циклу.
- Критерій: наявні UI-сценарії, переклади й доступність збережені; віджети
  використовують прикладні сервіси та не містять SQL або виконання OCR.

### TD-04 · Середній · Робота з великими обсягами даних

- Каталог фото обходиться повністю при оновленні, мініатюри читаються в UI-потоці,
  а статистика отримує всі записи для агрегації в Python.
- Виміряти затримки на великих каталогах і БД; додати фонове завантаження та кеш
  мініатюр, а агрегації статистики виконувати SQL-запитами.
- Критерій: зафіксовані вимірювання до/після; інтерфейс залишається чутливим,
  вибір фото не губиться, застарілі фонові результати відкидаються, експорт повний.

### TD-05 · Низький · Підтримка каталогів перекладів

- Самостійний Tk-оновлювач містить вбудовану копію `updater_*` перекладів;
  відповідність основному каталогу вже перевіряється тестом.
- Додати генерацію цієї копії з `serial_vision.i18n.TEXT`, зберігши запуск
  окремого скрипта без залежності від встановленого застосунку.
- Критерій: одна команда відтворює каталог без ручного дублювання; тест узгодженості
  та незалежність оновлювача залишаються обов'язковими.

### TD-06 · Низький · Актуалізація архітектурної документації

- `documents/architecture.md` описує застарілу схему БД і сценарій OCR.
- Описати поточні межі модулів, таблиці, фонові завдання, локальний API,
  перевірку оновлень і процес перевірок через uv/Makefile/CI.
- Критерій: документація відповідає поточному коду та містить посилання на
  центральний сценарій і команди перевірки.

## Закриті пункти

- Вихід завершує застосунок після закінчення фонових операцій і зупиняє камеру та API.
- Застарілі AI-відповіді не потрапляють у результати іншого фото.
- Помилки читання фото звільняють зайнятий стан; повторне розпізнавання доступне.
- Валідація API відхиляє порожні/некоректні записи; відсутні записи повертають 404.
- Фільтри дат включають дробові секунди останнього дня та переходи літнього часу.
- Поля фільтрів мають пов'язані підписи й локалізовані доступні назви.
- Додано uv із lock-файлом, Ruff, початкову перевірку типів і CI для PR/push.
- Окремий оновлювач має три мови, автовизначення мови ОС і перемикач;
  перелічені повідомлення OCR/AI/API/редагування фото та повтор журналу локалізовано.
- Вбудований оновлювач Windows/Linux блокує завантаження без коректного SHA-256,
  обов'язково перевіряє завантажений файл і показує локалізовані помилки.
  Покрито регресійними тестами.
